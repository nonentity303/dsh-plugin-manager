# dsh-plugin-manager-pro 0.8.3 — 只修 bug，不换界面

> **一句话**：如果你暂时不想换到 0.9 的新插件页，这个包把本批次修好的核心问题（插件开关、运行期诊断、下载安装、启动器、救砖）带回到 **0.8.x 的设置页界面**上。

本文件可直接作为 GitHub Release 正文使用。想要新插件页请安装 **0.9.0**（见同目录 `0.9.0.md`）。

## ① 版本定位

- 0.8.3 是**补丁包**：核心文件与 0.9.0 同源，但**客户端界面仍是 0.8.x 的设置页清单**。
- 与 0.9.0 的差别只有界面：**要新插件页装 0.9.0；只要修复装这个**。
- 基线是已发布的 0.8.3-1，在此之上更新核心文件；界面与 0.8.x 保持一致。
- npm 上的 0.8.x 最新版本是 0.8.2；本版请从本 Release 下载 tarball 安装（见 ④）。

## ② 新增与变化（现在你可以……）

| 现在你可以…… | 说明 |
|---|---|
| 用三个命令行工具管理启动器与救砖 | 新增 `dsh-pm-launcher` / `dsh-pm-boot` / `dsh-pm-rescue`（见 ④） |
| 一眼看清启动器 / 守护 / 引擎各自的真实状态 | `npx dsh-pm-launcher --status`：HTTP 握手结果、端口占用者、PID 文件、工作目录、日志位置、最后一次心跳 |
| 让启动器常驻、引擎挂了自动拉起 | `npx dsh-pm-launcher --supervise`（静默守护，锁端口保证只有一个实例） |
| 打开浏览器就自动自检启动 | 把主页设为 <http://127.0.0.1:3081/> |
| 开机自动就绪（Windows） | `npx dsh-pm-launcher --install-autostart`；`--autostart-status` 查看；`--uninstall-autostart` 移除。中文用户名 / 含空格路径不会再乱码 |
| 用独立救援页做诊断、修复、启停 | 不依赖主引擎，主引擎挂了照样能用 |
| 双击 `bin\dsh-boot.cmd` 完成"自检 → 修复 → 启动" | 失败时会打印引擎日志的绝对路径与退出码说明；`npx dsh-pm-boot --help` 看全部参数 |
| 把 `.tgz` 丢进下载目录自动安装 | 安装前会校验，失败自动回滚 |

> 说明：本版**没有** 0.9 的新插件页（侧边栏入口、5 个分区、官方内置（可选）分区、行内配置页）。插件管理仍然在设置页里。

## ③ 修复（现象 → 现在）

### 插件管理（界面仍是 0.8.x）

| 现象（修复前） | 现在 |
|---|---|
| 禁用/启用插件、应用场景方案后总是等到超时，并提示"需要重启" | 即时生效，不再空等超时、不再谎报需要重启 |
| 插件运行期报错在诊断与救援页显示为空白 | 能读到真实错误文本 |
| 自动隔离可能把界面 / 基础设施类插件也写成禁用 | 只隔离真正反复失败的插件（连续失败阈值），且自动隔离默认关闭、需显式开启 |
| 从下载目录丢进来的归档不校验就安装，失败后留残局 | 安装前校验，失败自动回滚 |
| Windows 上常因参数被拆开而装错包 / 装到同名包 | 参数按进程语义传递，含空格的路径也能正确调用 pnpm |

### 启动与救砖

| 现象（修复前） | 现在 |
|---|---|
| Windows 双击 `bin\dsh-boot.cmd` 必然失败（找不到脚本），还打印误导性的 FAILED | 双击即可用；失败时给出日志绝对路径与退出码说明 |
| 引擎起来后插件无法自我更新 / 卸载（文件被占用） | 引擎在稳定目录里运行，不再锁住插件包目录 |
| 守护"静默消失"，事后无法归因 | 守护写「状态变化 / 心跳 / 退出 / 未捕获异常」日志，`--status` 可查存活与端口归属 |
| 引擎起不来却报"已就绪"（端口上其实是别的程序） | 就绪 = HTTP 握手 + DSH 身份校验；占用者不是引擎时明确报错 |
| 救援页「停止引擎」可能杀掉无关进程 | 停止前做多重校验（进程存活 / 进程镜像 / 端口归属），不通过一律拒绝；需要时可在救援页强制停止 |
| 启动器参数被吞掉：只读命令变成真去监听端口 | 参数解析修正；无法识别的参数会提示 |
| 启动失败要空等很久，且不给日志路径 | 启动即失败会立即返回，并打印引擎日志的绝对路径 |
| 中文用户名下开机自启静默失效（包装脚本乱码） | 自启包装脚本正文纯 ASCII（路径在运行时自解析）并做回读校验，非 ASCII 自动换编码 |
| 3081 被别的程序占用时启动器/救援页"漂移"到别的端口 | 直接报错并给出占用者，不再静默换端口（避免浏览器主页指向别人的服务） |

## ④ 安装 / 升级 / 回退

```sh
# 安装（从本 Release 页下载 tarball）
dsh plugin --profile web add ./dsh-plugin-manager-pro-0.8.3.tgz

# 重启 web 后生效
dsh web
```

装好之后，命令行工具（在任意终端可用；也可在包目录里用 `node bin/…` 直接运行）：

| 命令 | 作用 |
|---|---|
| `npx dsh-pm-launcher --help` | 3081 网页启动器 / 常驻守护 / 自启管理：`--supervise`、`--ensure`、`--status`、`--autostart-status`、`--install-autostart`、`--uninstall-autostart` |
| `npx dsh-pm-boot` | 启动序列：自检 → 自动隔离坏插件 → 拉起引擎 → 等待就绪。`--repair-only` 只自检+修复；Windows 也可双击 `bin\dsh-boot.cmd` |
| `npx dsh-pm-rescue --port 3082` | 独立救砖守护（verify / fix / start / stop / status API） |

升级到新界面：`dsh plugin --profile web add dsh-plugin-manager-pro`（npm）或安装 `dsh-plugin-manager-pro-0.9.0.tgz`。

卸载：`dsh plugin --profile web remove dsh-plugin-manager-pro`，随后执行 `npx dsh-pm-launcher --uninstall-autostart` 清理开机自启。

## ⑤ 注意事项

- **界面仍是 0.8.x 的设置页清单**，不含 0.9 的新插件页。
- 下面两个**界面问题在本版仍然存在**，已在 0.9.0 修复，需要它们请安装 0.9.0：
  1. 第三方插件在该界面里**没有配置入口**（行内 ⚙ 不出现、配置页打不开）；
  2. 个别状态与按钮可能显示为**看不见**（配色令牌缺失导致对比度失效）。
- **与 0.9.x 不可混装**：升级 / 回退请整包替换（`dsh plugin add` 会按版本号重装），不要手工拼接文件。
- **端口分工**：3080 = 引擎与主界面；3081 = 启动器与救援入口（浏览器主页设为 <http://127.0.0.1:3081/> 即可"打开即自检启动"）；独立救砖守护默认也用 3081，需同时运行请显式 `--port 3082`。
- **开机自启**（Windows）：只由 `npx dsh-pm-launcher --install-autostart` 写入；卸载插件后请执行 `--uninstall-autostart`。

## ⑥ 已知限制

- **启用/停用插件后需要重启引擎才生效（本版没有重启提示）**：这一版用的引擎只在**启动时**套用插件条目，界面上做完启用/停用不会即时生效，也不会提示你去重启；请手动重启一次引擎（关掉 3080 的 `dsh web` 再启动，或打开 <http://127.0.0.1:3081/> 点"启动引擎并打开主界面"）。
  **需要"改完即时生效、并明确提示重启"的体验，请安装 0.9.0。**
- **可见启动窗口里看不到引擎日志**：双击 `bin\dsh-boot.cmd`、或由启动器弹窗（分离进程）拉起的窗口只显示启动进度，引擎自身的输出写在 profile 目录的日志文件里，**不会落在这个窗口**。需要全程输出时：用 `npx dsh-pm-boot` 在当前终端里运行（日志与进度都留在窗口内），或执行 `npx dsh-pm-launcher --status` 查看它给出的日志路径与最后一次心跳，也可以打开 <http://127.0.0.1:3081/> 的救援页查看自检/修复结果。
- **健康判定偏严格是有意的**：只有当端口上的服务真的完成 HTTP 握手并带有 DSH 身份时才判"已就绪"；3080 被别的程序占用时会拒绝启动并报出占用者。
- 插件市场与更新源依赖网络；代理/镜像环境可能需要在 profile 里调整 registry。
- 从下载目录自动安装归档需要 `pnpm` 可用。
- 本版是基于已发布 0.8.3-1 打补丁的派生包：只有核心文件被更新，界面与 0.8.x 完全一致。
