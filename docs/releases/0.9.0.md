# dsh-plugin-manager-pro 0.9.0 — 全新插件页

> **一句话**：插件管理从"设置页里的一个清单"变成了**独立插件页**——从侧边栏直接进入，在一个页面里完成看插件、装插件、配插件、卸插件、救引擎。

本文件可直接作为 GitHub Release 正文使用。

## ① 版本定位

- 适用人群：用 DSH 的 web 界面（默认 <http://127.0.0.1:3080/>）管理插件的所有用户。
- 本版主体是**客户端界面**：新插件页（接管内置插件页）＋ 一批界面问题修复。
- 同时包含本批次全部**核心修复**（插件开关、运行期诊断、下载安装、启动器、救砖）。
- 从 0.8.x 升级属于**整包替换**：界面完全换新，请按下文 ④ 的步骤安装后重启。

## ② 新增与变化（现在你可以……）

| 现在你可以…… | 说明 |
|---|---|
| 从侧边栏/插件池直接打开「插件管理」 | 新增独立插件页，不再挤在设置页里的只读清单里 |

## ③ 修复（现象 → 现在）

### 界面

| 现象（修复前） | 现在 |
|---|---|
| 第三方插件的配置入口在该页面里没有任何落点（行内 ⚙ 不出现、也打不开配置页） | 行内 ⚙ 与展开的配置卡片都有真实出口；没有注册配置的插件不会出现空按钮 |
| 个别状态与按钮显示为"看不见"（配色令牌缺失、对比度失效） | 相关按钮与状态正常显示（令牌缺失时自动回退到可读颜色） |
| 点「打开配置页」没有反应 | 配置页能真正打开 |
| 官方插件卡片只有标题、没有一行说明 | 卡片带一行简介（与内置插件页一致） |
| 切换语言后官方卡片仍是旧语言；后注册的插件不出现 | 清单跟随语言与插件注册实时更新 |
| 禁用/启用插件后页面跳回顶部 | 滚动位置保留 |
| 「插件市场」「操作与场景」等入口缺失或不可用 | 5 个分区齐备，市场可浏览与安装 |

### 核心（本批次一并修复）

| 现象（修复前） | 现在 |
|---|---|
| 禁用/启用插件、应用场景方案后总是等到超时并提示"需要重启" | 即时生效，不再空等超时、不再谎报需要重启 |
| 插件运行期报错在诊断与救援页显示为空白 | 能读到真实错误文本 |
| 自动隔离可能把界面/基础设施类插件也写成禁用 | 只隔离真正反复失败的插件（连续失败阈值），且自动隔离默认关闭，需显式开启 |
| 从下载目录丢进来的归档不校验就安装、失败留残局 | 安装前校验，失败自动回滚 |
| Windows 上常因参数被拆开而装错包 | 参数按进程语义传递，含空格的路径也能正确工作 |
| 引擎起不来却报"已就绪"（端口上其实是别的程序） | 就绪 = HTTP 握手 + 身份校验；占用者不是引擎时明确报错 |
| 救援页「停止引擎」可能杀掉无关进程 | 停止前多重校验（进程/镜像/端口归属），不通过一律拒绝，需要时可在页面强制停止 |
| 启动失败要空等很久且不给日志路径 | 启动即失败会立即返回并打印引擎日志的绝对路径 |

## ④ 安装 / 升级 / 回退

```sh
# 安装 / 升级（npm）
dsh plugin --profile web add dsh-plugin-manager-pro

# 或用 Release 页下载的 tarball（离线/自建场景）
dsh plugin --profile web add ./dsh-plugin-manager-pro-0.9.0.tgz

# 重启 web 后生效
dsh web
```

装好之后，命令行工具（在任意终端可用；也可在包目录里用 `node bin/…` 直接运行）：

| 命令 | 作用 |
|---|---|
| `npx dsh-pm-launcher --help` | 3081 网页启动器 / 常驻守护 / 自启管理：`--supervise`、`--ensure`、`--status`、`--autostart-status`、`--install-autostart`、`--uninstall-autostart` |
| `npx dsh-pm-boot` | 启动序列：自检 → 自动隔离坏插件 → 拉起引擎 → 等待就绪。`--repair-only` 只自检+修复；`--help` 看全部参数；Windows 也可双击 `bin\dsh-boot.cmd` |
| `npx dsh-pm-rescue --port 3082` | 独立救砖守护（verify / fix / start / stop / status API，不依赖主引擎） |

回退到旧版界面：安装上一版 0.8.x 包，例如 `dsh plugin --profile web add dsh-plugin-manager-pro@0.8.2`，然后 `dsh web`。

卸载：`dsh plugin --profile web remove dsh-plugin-manager-pro`，随后执行 `npx dsh-pm-launcher --uninstall-autostart` 清理开机自启。

## ⑤ 注意事项

- **界面换新、整包替换**：0.9 的独立插件页与 0.8.x 的设置页清单是两套客户端，请用 `dsh plugin add` 重装（它会按版本号替换），不要手工拼接文件。
- **端口分工**：3080 = 引擎与主界面；3081 = 启动器与救援入口（把浏览器主页设为 <http://127.0.0.1:3081/>，打开浏览器就自动"自检 → 修复 → 启动"）；独立救砖守护默认也用 3081，要与启动器同时运行请显式 `--port 3082`。端口被别的进程占用时，工具会**明确报错**而不是悄悄换端口。
- **开机自启**（Windows）：只由 `npx dsh-pm-launcher --install-autostart` 写入；卸载插件后请执行 `--uninstall-autostart`，否则自启项会指向已删除的包。`--autostart-status` 可随时查看。
- 第一次用可以把浏览器主页设为 3081：之后即使引擎起不来，打开浏览器就能自检修复并拉起。

## ⑥ 已知限制

- **可见启动窗口里看不到引擎日志**：通过 `bin\dsh-boot.cmd` 双击、或由启动器弹窗（分离进程）拉起的窗口只显示启动进度，引擎自身的输出写在 profile 目录的日志文件里，**不会落在这个窗口**。需要全程输出时：用 `npx dsh-pm-boot` 在当前终端里运行（日志与进度都留在窗口内），或执行 `npx dsh-pm-launcher --status` 查看它给出的日志路径与最后一次心跳，也可以打开 <http://127.0.0.1:3081/> 的救援页看自检/修复结果。
- **健康判定偏严格是有意的**：只有当端口上的服务真的完成 HTTP 握手并带有 DSH 身份时才判"已就绪"。因此 3080 被别的程序占用时启动器会拒绝启动并报出占用者 —— 请先结束它或改用其它端口。
- 插件市场与更新源依赖网络；代理/镜像环境可能需要在 profile 里调整 registry。
- 从下载目录自动安装归档需要 `pnpm` 可用。
- 启动器与独立救援守护默认共用 3081，同时使用需为其中之一指定其它端口。
- 本版按 DSH 0.1.7 的客户端槽位与引擎接口开发；更早的引擎版本未做兼容承诺（详见仓库 Releases 的兼容性说明，或先在测试 profile 试用）。
