# dsh-plugin-manager-pro 1.0.0-rc.2 — 引擎与插件管理台

> **一句话**：插件管理的三个入口（3080 管理台 / 3081 兜底页 / 救援中心）全部重做定型——列表按来源三分区、管理器自身的禁用与卸载口径统一、卸载/更新/体检全链路事务化，文案全面中性化。
> 日期：2026-11-24

本文件可直接作为 GitHub Release 正文使用。

## ① 版本定位

- 适用人群：用 DSH 的 web 界面（默认 <http://127.0.0.1:3080/>）管理插件的所有用户。
- 本版是 1.0 的发布候选（**dist-tag `next`**，`latest` 保持 0.9.1 不动）：在 rc.1 的 3081 兜底页与接管页基础上，完成 3080 管理台重做、核心链路加固与一致性修订。
- 从 0.9.1 升级：界面结构与文案均有变化（详见 ②③），核心 API 兼容；按下文 ④ 安装后重启引擎即可。

## ② 新增与变化

### 列表分区（按来源三分区）

| 分区 | 判定 | 行为 |
|---|---|---|
| 核心组件（引擎必需，不允许禁用） | 包名白名单（dsh-base / dsh-web-app） | 锁定展示，开关与卸载均拒绝 |
| 引擎内置组件 | 引擎自带（origin=builtin） | 可启停；行徽章「内置」，区内按名称排序 |
| 用户插件 | 用户安装（origin=user） | 完整操作：启停 / 更新 / 卸载 / 配置 |

- 「推荐」不再是分区：仅真正的第三方推荐加装件（如 browser-control）显示行内「推荐」标签，重要引擎组件不再混入推荐清单。
- 来源筛选（全部 / 架构自带 / 用户安装）、搜索、分区折叠与计数联动；来源支持人工修正并持久化。
- 界面文案中性化：去除拟人化措辞（「命脉」「救砖」→「核心组件」「救援」），中英文同步。

### 3081 兜底页（启动器原生，引擎不可用时可用）

- 扁平设计 + 深浅主题（工具栏「主题」按钮；自动跟随引擎外观与系统偏好，长按 0.6 秒复位为自动）。
- 搜索过滤、启停（写前自动备份）、`pnpm outdated` 批量更新、事务性卸载、mod 体检（verdict 三档：ok / suspect / broken）。
- 重启引擎 / 停止启动器：确认框 + toast，写接口全部走 Origin + 一次性令牌防护。

### 管理器自身的禁用与卸载（统一口径）

管理器不能在自身管理界面（3080）中停用自己；如需禁用或卸载，请前往启动器兜底页（3081 /plugins）或使用 dsh 命令行——兜底页独立于引擎存活，禁用后仍可恢复。

3080 内允许的例外是卸载：走额外警告路径，卸载前自动清理开机自启；3081 兜底页的行徽章同步改为「管理器·本页可禁用/可卸载（3080 界面内不可自禁）」。

### 其他

- 救援球：可拖动换位（localStorage 记忆），拖动松手不触发打开。
- 更新源一键更新（npm / GitHub / 插件市场聚合取最高）、下载目录自动安装、插件市场（dshfind 精选目录）、依赖关系感知、操作历史一键撤销、场景方案。

## ③ 修复

| 现象（修复前） | 现在 |
|---|---|
| 卸载失败可能留下半删状态或误回滚 | 事务性卸载：备份 → `pnpm remove` → 清理补丁条目 → 逐项验证，每步落日志、失败可回滚；`pnpm remove` 超时或进程状态不明时**不**盲目回滚，标记「未知」请人工确认 |
| 卸载/更新被运行中的引擎占用时硬删卡死 | EBUSY 引导：拒绝硬删，提示「先禁用 → 重启引擎 → 再操作」 |
| 启动器拉起引擎未透传 `--port`，引擎落到 3080 与启动器探测端口不一致（`EADDRINUSE` / 假健康） | 端口全链路透传，探测与实际一致 |
| smoke 把 `AbortError` 误判为「引擎已下线」 | 区分超时与真实下线 |
| EBUSY 报错直接抛原始异常 | `friendlyError` 输出可读指引 |
| 引擎起不来却报"已就绪" | 就绪 = HTTP 握手 + 身份校验（与 0.9.0 一致，继续保留） |

## ④ 安装 / 升级 / 回退

```sh
# 安装 / 升级（npm，注意 dist-tag 是 next）
dsh plugin --profile web add dsh-plugin-manager-pro@next
# 或离线 tgz（GitHub Release 附件与 npm registry 的 tarball 字节一致）
dsh plugin --profile web add ./dsh-plugin-manager-pro-1.0.0-rc.2.tgz

# 装完必须重启引擎：客户端 bundle 只在引擎启动时加载
dsh web
```

> pnpm 11 起 `minimumReleaseAge` 默认 1440 分钟且预发布号不会被 `latest` 解析到——请**显式写版本号**（`dsh-plugin-manager-pro@1.0.0-rc.2`）。

回退：

```sh
dsh plugin --profile web add dsh-plugin-manager-pro@0.9.1   # 显式版本号，重启引擎生效
```

## ⑥ 已知限制（不阻塞发布）

1. `dsh-boot` 弹窗启动路径不落 `web.log`，token URL 抓不到（`enginectl` 路径正常）——3081 页可能给不出可跳转的入口 URL，到 `/rescue` 执行一次「重启引擎」即可恢复。
2. `test-launcher.mjs` 会重写 `<DSH_HOME>/scripts/dsh-launcher.cmd`——测试时设 `DSH_HOME=<临时目录>` 隔离。
3. smoke 未覆盖卸载/更新真跑（靠 `--strict` + 手工真跑补）。
4. `RescuePanel` 的「mod 体检」是跳转入口（3080 跨源读 3081 未开 CORS）。
5. 生成脚本头注释的版本号写死 rc.1（仅注释文字，不影响功能）。
