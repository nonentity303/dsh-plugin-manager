# dsh-plugin-manager-pro 1.0.0 — 引擎与插件管理台

> **一句话**：插件管理的三个入口（3080 管理台 / 3081 兜底页 / 救援中心）全部重做定型——列表按来源三分区、管理器自身的禁用与卸载口径统一、卸载/更新/体检全链路事务化，并**完整吸收 0.9.1-rc2 预发布的兼容性与性能加固**（Node 18/20 修复、弱网韧性、bundle −67.9%）。
> 日期：2026-11-24

本文件可直接作为 GitHub Release 正文使用。覆盖 **0.9.1 → 1.0.0** 的全部变更：未单独进 `latest` 的 1.0.0-rc.1 / rc.2 两轮候选，**以及 0.9.1-rc2 预发布**（semver 上 0.9.1-rc2 < 0.9.1，走 dist-tag `next`，未进 `latest`；其全部修复已并入本版）。

## ① 版本定位

- 适用人群：用 DSH 的 web 界面（默认 <http://127.0.0.1:3080/>）管理插件的所有用户。
- 本版为 **1.0 正式版**（npm `latest`）：在 0.9.1 的独立插件页基础上，新增 3081 兜底管理页、完成 3080 管理台重做、核心链路（卸载/更新/体检/引擎生命周期）加固、全量文档一致性修订，并带入 0.9.1-rc2 的兼容性/性能加固（见下表）。
- **Node 18/20 用户必须升级到本版**：0.9.1 在 Node < 22.14 上有加载崩溃缺陷（见 ③ G1），0.9.1-rc2 与本版已修。
- 引擎兼容：`>=0.1.7-rc.2 <0.3.0-0`（0.2.x 实测通过）；老引擎（0.1.0-rc.6 ~ 0.1.5）请用 0.8.2。
- 从 0.9.1 升级：界面结构与文案均有变化（详见 ②③），核心 API 兼容；按下文 ④ 安装后重启引擎即可。
- 从 0.9.1-rc2 升级：直接装 1.0.0 即可，无破坏性变化（管理台 UI 重做为来源三分区）。

## ③ 变化与修复

### 变化

| 变化 | 说明 |
|---|---|
| **管理器自身的禁用与卸载统一口径** | 管理器不能在自身管理界面（3080）中停用自己；如需禁用或卸载，请前往启动器兜底页（3081 /plugins）或使用 dsh 命令行——兜底页独立于引擎存活，禁用后仍可恢复。3080 内允许的例外是**卸载**（额外警告路径，卸载前自动清理开机自启）；3081 行徽章同步改为「管理器·本页可禁用/可卸载（3080 界面内不可自禁）」 |
| **文案中性化** | 全量去除拟人化措辞（「命脉」「救砖」→「核心组件」「救援」），中英文与文档同步 |
| 兜底页启停与引擎状态一致 | toggle 直接写 `dsh.profile.bundles`，写前自动备份；启动器并入插件管理后 3081 同时具备启动页 / 兜底页 / 救援页三入口 |

### 修复（现象 → 现在）

| 现象（修复前） | 现在 |
|---|---|
| 卸载失败可能留下半删状态或误回滚 | 事务性卸载：备份 → `pnpm remove` → 清理补丁条目 → 逐项验证，每步落日志、失败可回滚；`pnpm remove` 超时或进程状态不明时**不**盲目回滚，标记「未知」请人工确认 |
| 卸载/更新被运行中的引擎占用时硬删卡死 | EBUSY 引导：拒绝硬删，提示「先禁用 → 重启引擎 → 再操作」 |
| 启动器拉起引擎未透传 `--port`，引擎落到 3080 与启动器探测端口不一致（`EADDRINUSE` / 假健康） | 端口全链路透传，探测与实际一致 |
| smoke 把 `AbortError` 误判为「引擎已下线」 | 区分超时与真实下线 |
| EBUSY 报错直接抛原始异常 | `friendlyError` 输出可读指引 |
| 启动器对无效 token 的拒绝过严（引擎 0.2.2 返回 303） | token URL 校验接受 303 / 200+`__DSH_BOOT__` |
| 引擎起不来却报"已就绪" | 就绪 = HTTP 握手 + 身份校验（与 0.9.0 一致，继续保留） |

### 自 0.9.1-rc2 一并带入的加固（该预发布未进 `latest`）

| 项 | 内容 |
|---|---|
| **G1（blocker）** | 0.9.1 在 Node < 22.14 加载即崩（顶层具名导入 `node:module` 的 `findPackageJSON`，该导出 Node 22.14 才有）→ 改命名空间导入 + 运行时特性检测 + 可移植回退解析器，静态门禁 `node tools/dev/compat-scan.mjs --root .` 守住（本版 `blocker=0`） |
| **F6** | `--uninstall` / `--uninstall-autostart` 修复跨 profile 误删自启：只删指向目标 profile 的值与死指针，其余报告不删；删前 reg export 备份 |
| **C-05~C-15（跨平台）** | 非 Windows 弹窗启动纯函数化（.command 脚本 + osascript 兜底 / gnome-terminal -- / konsole、xterm -e）+ 退出码校验；全局安装根多级兜底；端口归属 lsof→ss→/proc/net/tcp 兜底链；缺环境变量给显式诊断 |
| **弱网韧性（C-02/03/04/09）** | 网络失败不污染「无更新」负缓存（合流窗口 + 显式重试穿透）；refresh() 总预算 90s 到点中止在飞请求（客户端 240s→120s）；按源指数退避 + 熔断；404 与网络异常分文案（「网络不可达，可重试」） |
| **性能 P-01** | 客户端 bundle minify + 裁剪 zod 未用 locale → **796,658 → 254KB（−67.9%）**，gzip 约 66KB |
| **性能 P-02** | 宿主 README 简介结果级缓存（含负结果，TTL 5min + 包操作显式失效）→ 热快照文件探测 1,016 → 0 次、热中位 18.8 → 1.1 ms |
| **性能 P-05** | 搜索过滤 120ms 防抖 + 纯函数单测（清空搜索每键重建 199 行 60–86ms → 只重建一次） |

## ④ 安装 / 升级 / 回退

```sh
# 安装 / 升级（npm）
dsh plugin --profile web add dsh-plugin-manager-pro
# 或显式版本号（发版 24 小时内推荐）
dsh plugin --profile web add dsh-plugin-manager-pro@1.0.0
# 或离线 tgz（GitHub Release 附件与 npm registry 的 tarball 字节一致）
dsh plugin --profile web add ./dsh-plugin-manager-pro-1.0.0.tgz

# 装完必须重启引擎：客户端 bundle 只在引擎启动时加载
dsh web
```

> pnpm 11 起 `minimumReleaseAge` 默认 1440 分钟——刚发布的版本请**显式写版本号**（`dsh-plugin-manager-pro@1.0.0`）。

回退：

```sh
dsh plugin --profile web add dsh-plugin-manager-pro@0.9.1   # 显式版本号，重启引擎生效
```

## ⑥ 已知限制（不阻塞发布）

1. `dsh-boot` 弹窗启动路径不落 `web.log`，token URL 抓不到（`enginectl` 路径正常）——3081 页可能给不出可跳转的入口 URL，到 `/rescue` 执行一次「重启引擎」即可恢复。
2. `test-launcher.mjs` 会重写 `<DSH_HOME>/scripts/dsh-launcher.cmd`——测试时设 `DSH_HOME=<临时目录>` 隔离。
3. smoke 未覆盖卸载/更新真跑（靠 `--strict` + 手工真跑补）。
4. `RescuePanel` 的「mod 体检」是跳转入口（3080 跨源读 3081 未开 CORS）。
5. `README.en.md` 为 0.9.x 存档版（中文版已按 1.0 重写；英文版详见文内提示）。
