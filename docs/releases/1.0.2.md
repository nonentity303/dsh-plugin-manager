## ② 安全修复（CWE-494：下载未校验完整性）

> 触发来源：GitHub PR #4（自动化安全扫描工具提交）。报告的链条属实，本版做了**完整修复**而不是局部补丁。

### 2.1 攻击链（修复前）

1. 默认更新源启用了 **dshfind**（"插件超市"）
2. dshfind 在 GitHub 搜索 `topic:dsh-plugin <包名>`，**接受第一个 `package.json` name 匹配的仓库**——不校验 owner
3. 跨源取**最高版本** → 攻击者伪造 `v999.0.0` 直接赢过真的 npm 发布
4. 下载该仓库的 release 资产 / torrent / magnet / codeload 归档，**没有任何 hashCode 或签名校验**，还接受明文 `http://`
5. 装进 profile → 生命周期脚本与插件代码在 agent host 里执行

攻击成本：**一个免费 GitHub 账号** + 受害者使用默认更新流程。

### 2.2 修复内容

**A. 移除 dshfind 源（不是加固，是删除）**

该源从 v0.5.1 引入后**从未有过任何 provenance/安全加固**，其设计本质是"用搜索猜来源"。能加的校验（比对 npm 登记的 owner/repo）只能缩小面、不能消除；而且它唯一的增量场景（包在 npm 有、只在 GitHub 发新版）恰恰没有 npm 登记可做锚点，会必然拒掉。所以整体移除：

- `DEFAULT_SOURCES` 不再包含 dshfind；`fetchLatestDshfindVersion`、缓存、失败合流键、下载解析分支全部删除（不留死代码）
- 已装用户的侧车 `plugin-manager.json` 里若还有 dshfind 条目，**读取时自动剔除**；旧客户端再提交也会被宿主丢弃
- UI 源列表：**4 个变 3 个**（npm 官方 / GitHub 官方仓库 / npmmirror 镜像）；"恢复默认源"不再塞回 dshfind

**B. 下载器完整性校验（`lib/downloader.js`，三道门禁）**

| 门禁 | 挡什么 | 行为 |
|---|---|---|
| ① 明文传输 | 中间人替换 / 降级劫持 | 默认**拒绝一切 `http://`**（含 `https` 跟随重定向后落到 `http` 的降级） |
| ② 无从校验 | "伪造高版本 + 无摘要直装" | 拿不到可校验摘要的下载**默认拒绝**（fail-closed），且**不发起下载、不落盘** |
| ③ 校验执行 | 内容被替换 | 给了摘要就**强制校验**：sha512/sha1/sha256（支持 npm SRI 多算法取最强、base64 与 hex 两种形态）+ 可选字节数；**边写盘边算**，包再大也不整体进内存；不匹配就删文件并失败 |

摘要来源：npm 的 `dist.integrity`/`dist.shasum`、GitHub release 资产的 `digest`（`sha256:<hex>`）+ `size`。

**C. registry 版本权威化（`lib/aggregate.js`）**

- registry 源给出确定版本时，**其它源一律不参与比较** → 伪造的 `v999.0.0` 永远不会被选中
- registry 没有版本时才回退到其它源，并标记 `degraded`（界面可提示"版本来自非官方源，未经 npm 校验"）
- 同一信任层内并列仍是随机（保留原来的公平性）

**D. 顺带修掉一个源错配 bug**

按源名反查"哪个源提供了这个版本"时，旧逻辑查不到就**随便拿一个启用的源**——可能拿 GitHub 的版本用 registry 的装法去装（或反之），等于绕过权威判定。现在改为先按 URL 精确定位，再退回"名字唯一且类型一致"，都不行就明确报"更新源配置可能已变更"。

### 2.3 ⚠️ 行为变化（请务必读）

1. **"插件超市（dshfind）"源没了**。靠它发现"同名 GitHub 仓库有新版 release"的包，不再从那条路拿到版本；如果包在 npm 上有新版，照常从 npm 更新。不再会出现"某个伪造仓库 v999.0.0 提示可更新"。
2. **没有可校验摘要的下载默认被拒**。典型场景：自建 GitHub 仓库的 release 资产没有 `digest`、或用源码归档兜底。
   - 提示语会告诉你怎么开
   - 开启方式：profile 的 `cordis.patch.yml` 里给 `dsh-drydock` 加配置
     ```yaml
     - id: drydock
       config:
         security:
           unverifiedDownloads: allow   # 默认 deny
     ```
   - 开启后仍会**在回执里标注"未校验"**，不会静默放行
3. **摘要不匹配、明文 `http://` 永远拒绝**，不受上述开关影响——内容已被篡改 / 传输可被替换时没有任何理由放行。

## ⑤ 已知限制（如实）

1. **只有摘要、没有签名**：校验锚定在"registry/GitHub API 返回的摘要"上，挡的是**传输篡改**与"摘要与产物不符"，**挡不住恶意发布者**（谁能控制发布通道，摘要自然匹配）。真正的发布者身份校验需要 sigstore/attestation，本版未做。
2. **P2P 放行后确实无内容校验**：BT 分片 hash 只防损坏、不防恶意做种者替换。放行只能靠 `security.unverifiedDownloads: allow`，回执会明说。
3. **codeload 兜底仍用 movable tag**（`refs/tags/v<version>`），tag 可被重打。改用 commit SHA 的方案的评估已写在代码注释与交付说明里，**本版未实施**（需额外 GitHub API 调用 + 缓存）。
4. **`checkDownloads`（浏览器下载目录自动安装）不校验来源**：那是用户手动下载的文件，无法回溯来源。
5. **自定义更新源仍允许 `http://`**：registry 源走 pnpm 不经过我们的下载器；GitHub 源永远是 https。若你配置了明文 http 的内网 registry，其**版本查询**仍可用（无内容校验）。
6. `lib/remote.js` 的 source 类型枚举仍含 `"dshfind"` 字面量（只是超集，宿主不会再产出该类型）。
