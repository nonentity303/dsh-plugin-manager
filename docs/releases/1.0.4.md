## ④ 安全收口（1.0.3 攻击测试残留，2/2）

1. **引擎内救援路由补安全响应头**：`/rescue`、`/plugins-launcher` 的 200/401/403 响应统一带 `Content-Security-Policy`（`default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'`）、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`。救援页内联脚本/样式仍可运行。
2. **3082 rescue-daemon 补 Host 校验与安全头**：入口只接受 `127.0.0.1:<port>` / `localhost:<port>` / `[::1]:<port>`，其余 `421`；页面/API/421 全部带上述安全头；既有 Origin + 一次性令牌写接口判定不变。

**攻击测试证据**（1.0.3 隔离实例报告，2 项残留本版已收口）：3081 Host 伪造 421、DNS 重绑定（`127.0.0.1.nip.io`）421、CSP 真浏览器拦截外连、`log()` XSS 不执行、引擎救援路由 401/403/405 与跨站拒绝、下载目录投毒三态、更新源伪造 999.0.0 不胜出。

## ⑦ 已知限制（如实）

1. **只有摘要、没有签名**：校验锚定 registry/GitHub 摘要，挡传输篡改，挡不住恶意发布者；发布者签名（sigstore）未做。
2. **provenance 记录是本机信任**：`pendingDownloads` 在 profile 侧车，同用户可写；挡的是"别的程序往 downloads 丢包"，不是 OS 级隔离。
3. **`engines.node` 未收紧**（仍 `>=18.0.0`，实际建议 Node 22 LTS+）；收紧排 1.1.x。
4. **codeload 兜底仍是 movable tag**，本版未改。
5. **3080 RPC 的纵深防御**（报告 A S2）本版未动。
6. 英文详解文档暂未拆分，`README.en.md` 为精简入口，细节链接中文 docs。
