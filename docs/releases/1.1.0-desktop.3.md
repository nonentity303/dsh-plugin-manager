## 本轮修复：3080 与 3081 的 mod 列表对不上

**现象**（用户报）：同一个 profile，3080 插件页与 3081 `/plugins` 兜底页的条目数量/成员不一致。

**根因**：两页各读一份数据、各算一套分区。
- 3080 = `ctx.loader.entries()` → **只有已启用**的 bundle 有条目（被禁用的根本不出现）；
- 3081 = profile 清单 `dependencies ∪ dsh.profile.bundles` → 会列出"装了没启用""声明了没装"的；
- 分区：3080 用官方 `PROTECTED_PLUGINS / HIDDEN_BUNDLES`，3081 曾用硬编码 `CORE_BUNDLES`。

**修法**（两页同一套纯函数）：
1. `lib/bundles-official.mjs` 新增 `isEngineProvidedBundle()` —— 引擎自带（core / hidden）的 bundle 不在 `dependencies` 里是常态，不能被判成"悬空声明"（真机实测踩过）；
2. 3080 侧 `mergeProfileOnlyBundles()`：把清单里有、loader 没有的名字补成**只读行**（`enabled:false` + 明确理由 + 指向 3081 去启用），并标出 `dangling:`（声明了但没装，引擎加载会报错）；
3. 3081 侧 `classifyProfileBundles()`：三态 `enabled / disabled / dangling` + 与 3080 相同的 `section`（core / builtin / user）；
4. 兜底页补徽章（核心 / 引擎内置 / 用户 / 未启用 / 声明未安装）与说明文案。

**验证**：`test-mod-list.mjs` 14 项 —— 两页成员集逐字相等、同包名 section 相同、三态与引擎自带判定、核心组件两页同口径、被禁用项在 3080 也出现、悬空声明两页都报。

## 本轮新增：启动配置差异感知（`docs/review/DESIGN_1.0.5_启动配置差异感知.md`）

解决了"在 3081 禁用 wallpaper 后 3080 找不到、启用后还得重启"这类静默行为：

| 方案 | 实现 |
|---|---|
| **A** 启动快照 + 启动前 diff | `lib/boot-snapshot.mjs`：`<profile>/.plugin-manager/boot-snapshot.json`，**按引擎端口分键**、原子写、坏数据当无快照；`captureEngineState` / `diffEngineState`（added / removed / version-changed / patch-changed）；**只告警不拦启动**；启动成功后由 open-boot 写入 |
| **B** history 交叉核对定性质 | `classifyDiff()`：history 命中 → "上次管理台操作后没重启，本次启动已按当前状态加载"；未命中 → "配置变更未经过插件管理器，请确认来源" |
| **C** 跨引擎重启提示 | 3080 的开关返回里追加"3080 与 3081 兜底页共用同一个 profile，所有使用它的引擎都要重启才会收敛" |
| **D** supervisor 预检集成 | open-boot 拉起引擎前跑 diff，日志一行；兜底页新增「与上次启动相比的配置变更」卡片 |

**验证**：`test-boot-diff.mjs` 10 项（含 wallpaper 案例复现：启用态快照 → 3081 禁用 → 下次启动报"少了 wallpaper"且定性为用户操作）。

## 保留自上两个版本的内容

## 一句话

把 drydock 的控制面在桌面宿主上**降级为「编排层 + 只读诊断 + 离线修复」**：官方桌面已经把安装/启停/更新/卸载吃进 app，
drydock 只做官方覆盖不到的三件事——**离线只读诊断、官方恢复后自愈、走官方通道重建救援 profile**；
网页版行为与 1.0.4 一致（能力表在网页形态下全开，零回归）。

## 新增

- **首启环境探测 + 自动剥离**（`lib/envprobe.mjs` / `lib/capabilities.mjs` / `lib/host-profile.mjs`）：
  安装后首次启动探测宿主形态（`web` / `desktop` / `unknown`），把结论与证据原子写入 host profile；
  **非本环境的模块不会被加载**（惰性装载 + 剥离清单），`dsh-drydock-modules` 可随时审计"本环境永远不会执行的代码"。
- **能力门控**（M1）：一张能力表 + 中文理由，UI 按表渲染，**不散落 `if (isDesktop)`**；被关掉的入口可点开看理由。
- **来源防护 + CORS**（M2/M6）：桌面页面来源 `dsh-app://app` 走单独白名单；正式响应补 `Access-Control-Allow-Origin`/`Vary`；
  安全响应头与 1.0.3 的 `applySecurityHeaders` 合并（桌面与网页同一套）。
- **离线只读诊断**（M4）：`dsh-drydock-doctor`（人读 / `--json` / `--include-logs` / `--out`），不写盘、不碰锁、不启停进程。
- **官方目录三分区**（M3）：`lib/bundles-official.mjs` 直接读官方 `PROTECTED_PLUGINS`(17) / `HIDDEN_BUNDLES`(8) / `PROFILE_TEMPLATES`(5)，带静态回落副本。
- **恢复后自愈**（M5）：`dsh-drydock-boot --heal-recovery`（默认 dry-run，真写需双确认），从侧车与 `.rescue-bak-*` 重建被官方恢复埋掉的归属行。
- **官方通道救援 profile**（M5）：`dsh-drydock-boot --rescue-profile`（**桌面形态下拒绝执行**——绝不 spawn/kill 宿主）。
- **自更新**（`bin/drydock-update.mjs` + `lib/self-update.mjs`）：从权威源（npm https + `dist.integrity` SRI）或用户显式确认的本地 tgz
  取包 → 校验 → 暂存 → **「现在 / 稍后」** → detached worker（停引擎 → 装 → 健康检查 → 重启，失败自动回滚）。
  桌面形态**不自动装**（profile 由 Electron 独占），只提示；选了「稍后」下次启动由 3081 启动器再提醒。
  对应 RPC：`selfUpdateStatus` / `selfUpdatePrepare` / `selfUpdateDecide`；**3080 插件页工具栏下方新增「管理器自身」卡片**
  （有 pending 出「现在升级 / 稍后」两个按钮；桌面形态只显示提示文案；升级中显示"引擎会重启，完成后刷新本页"）。
  → [docs/自更新.md](../自更新.md)
