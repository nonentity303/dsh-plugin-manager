# dsh-drydock 1.1.0-rc.1 — 还名字债 + 兜底页体验修复（测试版）

> **一句话**：把 1.0.1 更名时**有意保留**的那一半命名债补齐（命令名 `dsh-pm-*` → `dsh-drydock*`，旧名留别名），并集中修掉一批"用户感知不到工具在干活"的兜底页问题。
> 日期：2026-11-26 ｜ **这是预发布版（rc.1），不是稳定版**

> ⚠️ **请先读这条**：本版**未在任何真实用户环境做完整验收**。
> 自动化测试（bundle / render / integration / launcher / 端口隔离 等 **452+ 项**）全绿，兜底页在隔离环境做过点击验证；
> 但**没有**在你的多插件真实 profile、也没有在 Windows 之外的平台上人工跑过全部入口。
> 想稳就等 1.1.0 正式版；想帮忙压测就装 rc.1 并回贴问题。

## ① 版本定位

- **发布形式**：npm dist-tag **`next`**（`latest` 仍是 1.0.1，不会被本次覆盖）；GitHub Release 标记 **pre-release**。
- **升级方式**（显式写版本，rc 不受 24h 冷静期影响那么严格，但显式更稳）：
  ```sh
  dsh plugin --profile web add dsh-drydock@1.1.0-rc.1
  # 重启 web 生效
  ```
- **回退**：`dsh plugin --profile web add dsh-drydock@1.0.1`
- **引擎兼容**：`>=0.1.7-rc.2 <0.3.0-0`（未变化）

## ② 命名债务清理（本版主线）

1.0.1 更名时只改了**包名与 loader id**，命令名当时**有意保留**（避免老用户脚本断）。本版把用户可见的那一半补齐：

| 旧命令（仍可用） | 新命令（推荐） | 说明 |
|---|---|---|
| `npx dsh-pm-launcher` | **`npx dsh-drydock`** | 主入口：唯一网页入口 + 常驻守护（3081） |
| `npx dsh-pm-boot` | **`npx dsh-drydock-boot`** | Steam 式启动序列 |
| `npx dsh-pm-rescue` | **`npx dsh-drydock-rescue`** | 独立备份救援守护（3082） |

- 旧命令**全部保留为别名**（`package.json` 的 `bin` 里两条指向同一文件），已写进脚本/快捷方式/文档的老命令**不会失效**。
- **启动链不受影响**（实测）：本机 `HKCU\Run` → `open-boot-autostart.vbs` → `scripts\dsh-open-boot.cmd` 用的是**绝对文件路径** `node_modules\dsh-drydock\bin\open-boot.mjs`，不经过 bin 名。
- 同步更新 5 份文档的命令示例（`README.md` / `README.en.md` / `docs/LAUNCHER.md` / `docs/README-full.md` / `docs/RELEASING.md`）。

**有意不改**（改了会断数据或断契约，别当遗漏）：
sidecar `plugin-manager.json`、备份目录 `.plugin-manager`、一次性令牌头 `X-DSH-PM-Token` / `<meta name="dsh-pm-token">`、环境变量 `DSH_PM_*`、RPC 命名空间 `pluginManagerPro`、类名 `PluginManagerPro`、以及**全部历史 release notes**（历史就该是历史）。

## ③ 兜底页（3081）体验修复

> 来自真实使用反馈："很多功能没有给用户反馈，使用时感知不到功能起效"、"mod 体检的卡片定位太靠后，大概率看不到"。

### 3.1 结果卡片前移 + 点击后自动滚动高亮

- **卡片顺序调整**：`更新检查结果` / `mod 体检` / `操作步骤日志` 三张"结果卡"从「用户插件」长列表**之后**移到工具栏**正下方**。它们是操作的结果，不是内容主体——列表再长也不该把结果顶出视口。
- **点击后自动到位**：`mod 体检` / `检查更新` / 卸载完成 都会自动 `scrollIntoView` 到对应卡片，并给 1.6s 高亮闪烁，让眼睛有落点。
- **直达链接**：3080 的「mod 体检」入口跳 `/plugins#health` 时，自动执行体检并滚到结果；新增 `hashchange` 监听（地址栏改 hash 也生效）。

### 3.2 每个入口都有"开始 + 结果"两段反馈

| 入口 | 改动前 | 改动后 |
|---|---|---|
| 刷新 | 完全静默 | 「刷新中…」→「已刷新：共 N 个组件（用户插件 N 个，已启用 N 个）」 |
| 检查更新 | 只禁用按钮、无开始提示 | 「检查中…」+ 开始提示 + 结果带前 3 个包名 |
| 🩺 mod 体检 | **零提示**，且接口异常会**永久禁用按钮** | 「体检中…」+ 汇总「正常/可疑/异常」计数（异常时点名）+ 卡片自动到位；`withBusy` 保证异常也恢复按钮 |
| 重启引擎 | 只禁用按钮 | 「重启中…」+ 「最长约 30s」+ 成功后给出入口地址 |
| 停止本启动器 | 无发起提示 | 「停止中…」+「引擎与本页面不受影响」 |
| 行内启停开关 | 只有结果、无发起提示 | 行变暗 + 「正在禁用 X…」→「已禁用 X，重启引擎后生效」 |
| 更新 / 卸载 | 部分路径静默、失败只说"失败" | 全程有发起/取消/结果；失败带**具体原因**（含 engine-busy 引导） |
| 市场详情 | **完全静默**（弹窗被拦也不知道） | 成功提示已打开；被拦时给出手动 URL |
| 核心组件开关 | 点了**毫无反应**（禁用的 input 吞掉鼠标事件） | 解释性提示「X 是引擎必需的核心组件，不能在这里禁用…」 |
| 主题 | 只有颜色变化 | 补一句"本页记忆；长按复位为自动" |
| 确认框「取消」 | 静默 | 四类写操作取消都有"已取消"回执 |

### 3.3 顺带修掉三个反馈类 bug

1. **体检/更新接口抛异常 → 按钮永久禁用**（`disabled=false` 写在 `await` 之后，异常就跳到不了）→ 统一 `withBusy` + `finally`。
2. **启动页 409（已有启动流程在跑）只写一行日志、spinner 永转** → 补 `stopSpin()` 与明确提示。
3. **toast 浮层盖住按钮会吃掉点击** → `#toasts{pointer-events:none}`（实测 `elementFromPoint` 已穿过）。

> 原则：**步骤日志保留留档，toast 负责感知**。两者不互相替代。

### 3.4 另两个页面同步检查

- `/`（启动页）：补「已等待 N 秒」计时 + 结束后的逐行结论输出，不再是"转圈到天荒地老"。
- `/rescue`（救援页）：五个按钮全部补「…中」发起文案 + 完成/取消回执，并防重复点击。

## ④ 稳定性修复

- **`test-launcher.mjs` 的高位端口假失败**（既存 flake，本版定位并修掉）：`freePort()` 可能取到 >64535 的临时端口，而守护锁端口 = 启动器端口 + 1000 越过 65535 → `lockPortOf()` 返回 `null` → open-boot 报"探测不可用"，导致 3 条 F2 断言**偶发假失败**。现在 `freePort()` 按产品约束（≤64535）在安全区间取端口。

## ⑤ 本版**不包含**：桌面版支持

DSH 桌面版（Electron）相关能力（能力门控 / 离线只读诊断 / 恢复后自愈 / 官方 rescue profile 通道 / CORS 预检）**已完成但未随本版发布**，整体封存在仓库分支 `desktop-support-wip`，等真机验证通过后作为下一个版本（1.2.0）合入。

> 为什么不一起发：桌面版支持会写 `profiles/desktop`、影响写接口来源白名单，**必须先在真机验过**才适合发给用户；而命名债与 UX 修复与桌面无关，先发能让用户早受益。

## ⑥ 升级注意

- **老用户无感**：旧命令、侧车数据、备份、归属标记、引擎兼容范围全部不变。

- 客户端 bundle 变了 → **必须重启 web 生效**。
