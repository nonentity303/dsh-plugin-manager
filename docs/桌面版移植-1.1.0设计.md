## 0. 一句话定位

**桌面版不是"加个 target"，是把 drydock 的"控制面"降级成"编排层 + 只读诊断 + 离线修复"。**
网页版保持"我全权负责"，桌面版承认"应用负责执行，我负责判断、记录、修下一次启动"。

## 2. 能力门控表（唯一的移植机制）

**不许散落 `if (isDesktop)`。** 一处探测 → 一张表 → UI 按表渲染。

```js
// lib/capabilities.mjs
export const CAPABILITIES = {
  web: {
    id: "web",
    takeoverOfficialPage: true,   // 停用内置 ui-plugin-manager 并接管
    livePnpmOps: true,            // 现跑 pnpm 增删
    hotToggle: true,              // 写 patch 行 + 重启引擎生效
    autostart: true,              // HKCU Run + wscript→node
    browserLauncher: true,        // 3081 浏览器即启动器 / open-boot
    market: true,                 // dshfind 精选目录
    scenarios: "read-write",
    rescueDaemon: true,           // 3082 独立救援守护
    engineLifecycle: "own",       // 自己 spawn / kill / 重启
    offlineDiagnostics: true,
  },
  desktop: {
    id: "desktop",
    takeoverOfficialPage: false,  // 撞 PROTECTED_PLUGINS + app 级插件页
    livePnpmOps: false,           // 需 Electron 完全退出；持锁时一律拒绝
    hotToggle: "gated",           // 允许：可逆 + 有备份 + 只动自己归属行
    autostart: false,             // 官方托盘 / 后台任务已覆盖
    browserLauncher: false,       // 降级为诊断入口
    market: false,                // 交给官方 bundle + dshmarket
    scenarios: "read-only",
    rescueDaemon: true,           // ← 桌面版唯一主战场
    engineLifecycle: "delegated", // 绝不 spawn/kill Host，只提示"从托盘完全退出"
    offlineDiagnostics: true,
  },
};

// 未识别形态 → 退回 web 表（保证网页版零回归）
export function capabilitiesFor(kind) {
  return CAPABILITIES[kind] ?? CAPABILITIES.web;
}
```

**UI 约定**：被关掉的每一项都要能点开看**一句话理由**（"灰着但告诉你为什么"），不许"能点但失败"。
**web 侧行为一行不改**——它拿到的是全 true 表，这就是"不干扰网页版"最硬的保证。

## 3. 环境探测（`lib/envprobe.mjs`）

纯函数 + 可注入（fs/env/exec 全可替换），**不做网络、不写盘**。

```js
/**
 * @typedef {object} EnvProbe
 * @property {"web"|"desktop"|"unknown"} kind
 * @property {string|null} reason          判定依据（人类可读，中文）
 * @property {number} confidence           0..1
 * @property {string} dshHome              权威 DSH_HOME（见下方解析顺序）
 * @property {string[]} homeCandidates     检测到的所有候选 home（含来源说明）
 * @property {string|null} profileName     当前 profile 名
 * @property {string|null} profileDir      profile 绝对目录
 * @property {boolean} desktopLockPresent  profiles/desktop/lock 是否存在
 * @property {string|null} desktopLockText lock 文件内容（截断 200 字符）
 * @property {string|null} hostVersion     从 app 侧/包侧探到的宿主版本（可能 null）
 * @property {string|null} hostVersionSource  "package.json" | "desktop-runtime.json" | null
 * @property {number[]} portCandidates     端口候选（有序，去重）
 */

export function probeEnv({ env = process.env, fsx = null, homeDir = null } = {}) {}
export function detectHomeCandidates({ env, homeDir }) {}   // 返回 {authoritative, candidates[]}
export function detectDesktop({ fsx, dshHome }) {}          // {locked, lockText, profileDir, initialized}
export function probeHostVersion({ fsx, dshHome }) {}       // {version, source}
export function resolvePortCandidates({ env, healthFn }) {} // 有序候选，不试连
```

**DSH_HOME 权威化（解析顺序，必须按序，且报告"检测到 N 个候选"）**
1. `process.env.DSH_HOME`（显式）
2. `$DSH_HOME` 与桌面 `userData/harness` **同时存在且不同** → 两个都报，`authoritative` 取环境变量，并置一条 warning
3. `~/.dsh`（默认）

**桌面判定（任一命中即 desktop，取最高置信度，全部记录 reason）**
- `ELECTRON_RUN_AS_NODE` 存在且父进程链含 desktop 可执行（confidence 0.9）
- `<dshHome>/profiles/desktop` 存在且**已初始化**（有 `package.json` 或 `lock`）（0.8）
- profile 目录名为保留名 `desktop`（0.7）
- `<profileDir>/.dsh-market/state.json` 存在（0.5，辅助）
- 端口候选里探到的实际监听端口 ≠ 配置端口（0.4，辅助）

**端口候选（有序，去重，上限 8 个）**
```
DSH_ENGINE_PORT → profiles/<p>/.open-boot.pid 记录的端口 → 3080 → 已观测端口（调用方传入）
```
桌面场景**额外**允许调用方传入"从 Electron 进程 `--port` 参数或 `netstat` 观测到的端口"；
`resolvePortCandidates` 只产**候选**，实际验证仍由现有 `engineHealth(port)`（HTTP 握手 + dsh 身份指纹）负责——**不许用裸 TCP 通过就当引擎**。

**BOM 防护**：所有读 patch/JSON 的函数遇到 UTF-8 BOM 必须**报告并剥离**（不静默）；
写盘一律无 BOM（`"utf8"`）。`writePatchFile` 前若目标是 BOM 文件 → 记录一条 `bom-stripped` 事件。

## 5. 红线（违反即返工）

1. **不写 desktop profile 的 `state.json`、不删 product patch 行、不做 `pnpm remove`**（Electron 持锁时）。
2. **不 spawn / kill 桌面 Host**；桌面版 `engineLifecycle: "delegated"`，只提示"请从系统托盘完全退出后重开"。
3. **不假设端口 / 不假设 `~/.dsh` / 不解析日志拿 token**（F1/F2）。
4. **不接管桌面插件页**（撞 `PROTECTED_PLUGINS`；官方 #2403 已证明这类失效是**静默空白**）。
5. **桌面版不自启**（`--install-autostart` 在 desktop 场景必须**拒绝并说明原因**，不是静默跳过）。
6. **web 侧零回归**：M1–M5 全部完成后 `node build.mjs && node test-bundle.mjs && node test-render.mjs` 必须与改前一致全绿。
7. **不新增运行时依赖**（不许 import `electron`）；`@deepseek-ai/dsh-official-bundles` 只允许**动态 import + 静态回落**，不许进 `dependencies`。
8. **UI 文案中文**；文件编辑只用 read/write/edit 工具，不用 PowerShell 写含中文的 UTF-8 文件。
9. **不许静默失败**：所有降级/跳过都要有可读中文原因 + 机器可读 code。

## 6. 验收方式（无桌面版也能全绿）

每个模块必须自带可复跑测试，且**不依赖真实桌面版**：

- 统一风格：`node test-<module>.mjs`，输出 `RESULT: PASS|FAIL` 行，退出码 0/1。
- 桌面场景全部用 **fixture 目录**：临时目录里造 `profiles/desktop/{package.json,lock,cordis.patch.yml,plugin-manager.json}`。
- 涉及 Electron 进程的判定，用**注入的假 `processTree` / 假 env**，不要真去枚举进程。
- 每个模块的测试必须包含一条**"web 场景行为不变"**的断言（防回归）。
- 提交前 lead 统一跑：`node build.mjs && node test-bundle.mjs && node test-render.mjs && node test-capabilities.mjs && node test-origin.mjs && node test-diagnostics.mjs && node test-rescue-profile.mjs`

### 8.1 真包静态分析带来的三处校准（本契约初版之后的修正）

1. **端口不用猜**：`profiles/desktop` 与 `lock` 是**确定路径**（真包 `lib/main.js:7612-7617`），端口反而是随机且不需要知道的。初版把"端口发现"当重点，实际重点是 **profile/lock 定位**。
2. **`dsh-app://app` 精确确认**：真包自己校验自家来源用的就是 `!== "dsh-app://app"`（无斜杠）。M2 的实现无需改。
3. **补出 M6**：真包 `registerSchemesAsPrivileged` 里 `corsEnabled: true` → 跨源 fetch 必走预检。M2 只做了服务端来源判定，端到端仍会被浏览器拦。M6 补齐预检 + 正式响应头。

### 8.2 一条重要的团队发现（记下来，别再踩）

`node build.mjs` 在本会话的 workspace-write 沙箱下会 **`spawn EPERM`**（esbuild 需要 spawn 子进程）。
→ 改了 `src/client.jsx` 后**必须**用提权模式跑一次 `node build.mjs`，否则 `lib/client.js` 还是旧的、补丁不生效。
（S2/S3 都踩了这条并如实上报；最终由 lead 提权构建，产物 263,250 → **263,317 B**。）
