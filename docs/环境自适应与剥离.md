# 环境自适应与「剥离」（1.1.0 起）

> 一句话：**装完第一次启动就探测出宿主形态，把不属于这个形态的代码从加载路径上摘掉（连 `import` 都不发生），
> 并输出一份"本环境永远不会执行的文件 + 行数"清单。** 目的是让"死代码审查"从脑力活变成可执行的表。

## 为什么需要它

桌面版支持（M1–M6）实测是 **+9,375 / −44** 的改动，其中 `lib/` 下 5 个桌面模块 4,683 行。
合并进主线后，审阅者会天然担心两件事：

1. **副作用**：网页用户会不会被桌面代码拖慢/拖崩？
2. **审查成本**：一眼看去半个仓库都是"桌面用得到、网页用不到"的代码，逐行甄别不可持续。

本机制把这两件事拆开解决：**能装的不装**（副作用）+ **不装的列出来**（审查成本）。

## 三层结构（每层都能单独断言）

| 层 | 文件 | 做什么 | 怎么验 |
|---|---|---|---|
| ① 形态判定 + 首启落盘 | `lib/host-profile.mjs` | 显式覆盖 `DSH_DRYDOCK_HOST` 优先；否则 `lib/envprobe.mjs` 的 `probeEnv()` 实测；结论 + 证据 + 能力表 id **原子写**进 `<DSH_HOME>/.drydock/host-profile.json`（TTL 30 天） | `test-host-strip.mjs` 12 项 |
| ② 能力表 | `lib/capabilities.mjs` | 每个形态一张能力表 + 每个能力一句中文理由（UI 灰置文案与剥离理由**同源**） | `test-capabilities.mjs` |
| ③ 模块登记 + 惰性装载 + 剥离清单 | `lib/host-registry.mjs` | `ENV_MODULES` 登记"环境专属模块 + 所需能力"；能力不满足 → **不 import**；`auditModules()` 输出文件 + 行数 | `test-host-strip.mjs` 7 项 |

## 用起来是什么样

```sh
# 首次启动（open-boot 拉起 3081 时）自动探测并落盘，只打印一行：
[open-boot] 首启环境探测：web · 未发现桌面版证据（…），按网页版处理：能力表全开（零回归）。

# 随时审计（不 import 任何环境专属模块）
npx dsh-drydock-modules
npx dsh-drydock-modules --audit     # 只列"本环境永远不会执行的文件 + 行数"
npx dsh-drydock-modules --json      # CI / issue 里直接贴
npx dsh-drydock-modules --refresh   # 换机器/换安装方式后强制重探测
npx dsh-drydock-modules --load      # 真正装载适用模块（验证"该装的装得起来"）
```

本机实测（2026-11-27，两种形态）：

| 形态 | 装载 | 剥离 |
|---|---|---|
| `web` | `rescue-profile`(1331 行) · `diagnostics`(1847 行) · `bundles-official`(351 行) | 无 |
| `desktop` | `diagnostics` · `bundles-official` | **`rescue-profile` 1331 行**（能力 `engineLifecycle=delegated`，桌面版绝不 spawn/kill Host） |

## 三条硬边界（避免"看起来做了更多"）

1. **剥离是文件级的**：一个模块整体装载或整体剥离，做不到"同一文件里删几行"。
   → 环境专属逻辑必须**独立成文件**（这也是 `test-isolation.mjs` 的 host import 白名单立得住的前提）。
2. **剥离 = 不 import**，不是"import 了但不用"。`loadModules` 支持注入 loader，测试可以断言"一次都没调用"。
3. **不写别人的东西**：只写自己的 sidecar `<DSH_HOME>/.drydock/host-profile.json`；
   不写 profile 的 `package.json` / `state.json` / `node_modules`，不碰桌面锁。
   `dsh-drydock-doctor` 是**只读**的：没有画像时干跑探测、**不落盘**（它的"fixture 跑完一字节不变"断言仍在）。

## 未知形态与安全默认

- `unknown`（例如只有未初始化的 `profiles/desktop` 目录）→ **不启用任何桌面专属行为**，能力表按网页版回落。
- 显式覆盖 `DSH_DRYDOCK_HOST=web|desktop` 供测试与运维；非法值被忽略并留证据（不静默生效）。
- 缓存损坏 / schema 不符 / 超 TTL → 重新探测并覆盖（不做迁移代码，避免历史包体越堆越多）。
- 探测或写盘失败**绝不阻塞启动**：引擎起不来的机器上，启动页更要拉得起来。

## 新增一个环境专属模块怎么做

1. 逻辑独立成文件（`lib/xxx.mjs`），**不要**塞进 `lib/index.js` 或已有的 bin；
2. 在 `lib/host-registry.mjs` 的 `ENV_MODULES` 里加一条：`{ id, file, capability, expect, why }`；
3. 跑 `node test-host-strip.mjs`（含"登记表里的文件都真实存在"断言）与 `npx dsh-drydock-modules --audit` 看它是否进了剥离清单。
