# 自更新（drydock 升级自己）

> 一句话：**从权威源拿到合法包 → 校验 → 暂存 → 问你"现在/稍后" → 停引擎 → 装新包 → 健康检查 → 重启；失败自动回滚。**

## 为什么不能"直接 pnpm update 就完事"

1. **正在跑的代码不能用自己替换自己**：更新要改 `<profile>/node_modules/dsh-drydock` 里的文件，而 3080 引擎正加载着它；
   Windows 上文件锁会让替换失败或留下半成品。→ 所以执行体是**脱离父进程的 detached worker**，父进程先停引擎再让 worker 干活。
2. **"合法包"必须可验证**：供应链投毒（CWE-494）的入口就是"下载了什么就装什么"。
   → 只认 npm 官方 registry 的 **https tarball + `dist.integrity`（SRI）**，逐字节校验，不匹配就删文件、不落盘。
3. **装坏了要能退回**：新版本可能起不来。→ worker 装完必须**健康检查**（HTTP 握手 + 身份标记），失败自动回滚到 `currentVersion`。

## 用法

```sh
# ① 只查（不下载、不写状态）
dsh-drydock-update --check

# ② 下载 + 校验 + 暂存，然后打印「现在 / 稍后」
dsh-drydock-update --fetch

# ③ 现在升级（起 detached worker：停引擎 → 装 → 健康检查 → 重启；失败回滚）
dsh-drydock-update --now

# ④ 稍后（保留暂存，下次启动由 3081 启动器再提示一次；--now 可随时继续）
dsh-drydock-update --later

# ⑤ 看进度 / 结果
dsh-drydock-update --status
dsh-drydock-update --status --json

# ⑥ 用本地 tgz（没有权威源可对照，必须显式确认来源）
dsh-drydock-update --accept-local .\dsh-drydock-1.1.0-desktop.2.tgz

# ⑦ 失败后手动回滚
dsh-drydock-update --rollback
```

常用参数：`--home <DSH_HOME>`、`--profile <名|目录>`（默认 `web`）、`--form <web|desktop>`、`--dsh <命令>`、`--registry <https 源>`、`--no-restart`（只装不重启）。

## 门禁（任何一条不满足就拒绝，fail-closed）

| 门禁 | 行为 |
|---|---|
| 权威源必须是 **https** | `--registry` 非 https 直接用法错误；packument 与 tarball 也各自校验 https |
| 包名必须一致 | packument 的 `name` ≠ 本包名 → `name-mismatch`（防同名镜像/拼写劫持） |
| 必须有 SRI 摘要 | `dist.integrity` 缺失或不是 `sha512/sha384/sha256-` → `no-integrity`（不能让"只给大小"过关） |
| 只升不降 | 目标 ≤ 当前 → `up-to-date` / `downgrade-refused`（`--force` 才允降级；回滚走 `--rollback`） |
| 通道由形态决定 | web → `latest`、desktop → `desktop`、形态未知 → 按 web（宁可少更新，也不擅自升桌面通道） |
| **桌面形态不自己装** | 桌面 profile 由 Electron 独占（官方 CLI 直接拒绝），所以只提示、不提供 `--now` |
| 本地 tgz 需显式确认 | `--accept-local` 才接受，并在状态里标 `source=local-file`、提示里明写"未经权威源比对" |

## 状态机与文件

```
<DSH_HOME>/.drydock/self-update.json        状态（原子写：tmp + rename；坏数据/旧 schema → 自愈为"无待处理"）
<DSH_HOME>/.drydock/self-update/<版本>.tgz  已校验的暂存包（--now 装的就是它）
<DSH_HOME>/.drydock/self-update-worker.log  worker 日志（--status 出问题先看这里）
```

阶段：`pending`（已暂存、等决策）→ `running`（worker 在跑）→ `applied` / `failed`（带 `rollback` 结果与 `lastError`）。
`running` 是不可中断的中间态：如果进程不在了，`--status` 会提示"请判定并手动回滚"。

## worker 的固定顺序（`test-self-update.mjs` 断言的就是这个顺序）

```
探测引擎状态 → 停引擎 → dsh plugin --profile <p> add <暂存 tgz> --config.minimumReleaseAge=0
  → 启动引擎 → 等健康（HTTP 握手 + 身份标记）
  ├─ 全绿 → applied
  └─ 任一步失败 → 装回 currentVersion → failed（写明 rollback 结果；回滚也失败就如实报失败，不谎报）
```

## 现在能用 / 还没接的

| 项 | 状态 |
|---|---|
| 权威源检查、合法性门禁、暂存、状态机、worker、回滚 | ✅ 已实现，`test-self-update.mjs` 22 项覆盖（注入式，无网络/无 pnpm） |
| 3080 启动器启动时的「有待安装更新」提醒（选了「稍后」后下次启动再提示） | ✅ 已接（`DSH_DRYDOCK_NO_UPDATE_PROMPT=1` 可关） |
| CLI 的「现在 / 稍后」提示文案（UI 与脚本共用同一段文本） | ✅ `dsh-drydock-update --prompt` |
| **3080 客户端里的图形弹窗（现在/稍后两个按钮）** | ⏳ **未接**：需要 host RPC（`remote.js` + `index.js` 暴露 pending/decide）+ `src/client.jsx` 的对话框 + 重建 bundle；文案与状态机已就绪，接的是"展示层" |
| 3081 兜底页上的提示条 | ⏳ 未接（同上，读状态 → 两个按钮 → 调 CLI 等价动作） |

> 设计原则：**提示可以在任何界面**，但"执行"只有一个入口（`dsh-drydock-update --now` / worker），避免多份安装逻辑互相打架。
